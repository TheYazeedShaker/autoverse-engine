# Build order

The merge as a sequence of PRs, under `CLAUDE.md` rule C:

- **2–3 PRs per page.**
- **Database, security and money changes in their own PR first**, merged by the owner before anything that needs them.
- **Every PR is opened against `main`, never stacked.** The work stops after each PR for the owner's merge.

Decisions are cited as **D*n*** ([`decisions.md`](decisions.md)). The plan assumes the recommendations there; a different answer changes the affected rows.

## Gates

Every PR passes the merge wall (production plan §10) and the gate before every push (`CLAUDE.md`):

1. root lint;
2. `turbo typecheck test --force`;
3. format;
4. the consumer build.

The extra gates by PR type:

| Code      | Applies to           | Gates                                                                                                                                                                                                                                                                                                                                                                                              |
| --------- | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **G-doc** | documents            | Format; secret scan; a manual no-real-names check (ADR 0008). CI has no automated names check                                                                                                                                                                                                                                                                                                      |
| **G-db**  | migrations           | RLS policy in the same migration as each table; paired cross-tenant isolation test; an aal1-token refusal test for staff policies; SQL tests in CI; a hosted pre-check query for every constraint that live rows could fail; regenerated `database.types.ts`; `security-review`; the owner merges and confirms the hosted apply                                                                    |
| **G-fn**  | edge functions, jobs | Unit and integration tests; Zod on both sides; a timeout, a retry policy (idempotent only) and a degraded mode on every external call; structured logs with the trace id, a metric and at least one alert; `security-review`; the owner deploys                                                                                                                                                    |
| **G-ui**  | pages and components | Strict types; no hex or px outside tokens; component tests; axe on every story in both themes (and both directions where the page has Arabic); reduced motion; the rule-B visual compare at 390/768/1440, shown in the chat; the route's initial-JS ceiling (D31); the page's E2E critical flow; a flag (default off) with a tested kill path; `code-reviewer`, plus `security-review` where noted |

**Sizes:**

- **S**: about a day or less.
- **M**: 2–3 days.
- **L**: 4–6 days.

**Switch-off** marks the point where a live Nmesis admin page hands over, by D14's rule:

1. The Engine page is live behind its flag, read-only, reading synced data.
2. After a 5-working-day hold (10 for Finance), it becomes the writer and the Nmesis page's writes are refused.
3. After a second hold, the Nmesis route redirects.

Each page's DB and function PRs come first, on their own.

**Value order, and why:**

1. **Overview** (read-only; it proves the stack).
2. **System** (staff must be managed where they sign in).
3. **Leads** (PII; the brands' daily need).
4. **Catalog** (the core daily work; it feeds the consumer port).
5. **Brands** (the commercial operations; it also completes the catalogue's switch-off).
6. **Settings, Monitoring and Analytics.**
7. **Plans and Finance** (money; a design is needed first).
8. **Brochures** (decision and design needed first).

- **Phase 1:**

Brand users are new `profiles` with a `brand_role`, separate from the AI Studio's members.
